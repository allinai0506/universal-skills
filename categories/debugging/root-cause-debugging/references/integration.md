# 接入现有工程流程

## AGENTS.md 只增加入口

先核对已有规则并去重；不要整份替换用户的 AGENTS.md。
下列文本是可选补充，不会由技能自动写入：

```markdown
## Bug 修复
处理缺陷、回归或修复验收时，加载 root-cause-debugging 技能。
按事实复现 → 因果验证与影响分析 → 最小完整修复与回归验收执行。
复用本仓库工程协议；结论附证据、实际验证结果与未验证边界。
紧急止血单独标记，不能作为根因关闭。
```

详细工程协议已有同等要求时只加技能链接。既有权限、测试、代码规范和发布要求继续有效。
不把完整技能正文复制到 AGENTS.md，也不让普通文案改动触发根因诊断全流程。

## 可选的 CI 接入

第一阶段只人工使用，不改 CI、不改 HAFlow 引擎。
第二阶段验证记录稳定后，在现有 CI 中显式增加下面的调用，路径按实际仓库修改：

```bash
python3 .agents/skills/root-cause-debugging/scripts/check_evidence.py   docs/bugs/BUG-001/evidence.json --phase close
```

该命令不会自行遍历或认定哪些 PR 属于缺陷修复。触发条件、缺少记录时失败的策略及所需检查，
须由仓库现有工作流配置；无人调用脚本时它不会阻止合并。
引用证据文件须包含在可读工作区，或由 CI 下载脱敏产物到指定 evidence-root。
脚本不执行证据记录里的命令；真实测试必须由 CI 的受信任步骤独立执行并保存产物。
保护校验器、工作流与规则变更，不能把 Agent 写下的 pass 字段视为可信执行结果。

## 与 HAFlow 结合的最小边界

本包没有读取当前 HAFlow 仓库，也没有假设任何现有 API、字段或数据库表已经存在。
以后接入时，先读取当前代码和协议，把“诊断结论/证据路径/测试结果”映射到已有任务产物。
优先复用已有轨迹与观察记录，通过其真实标识引用证据；不要另建一套事实源。

仅作为待验证映射：诊断节点产出证据，执行节点产出补丁，验收节点核验原始结果。
是否需要阻塞状态、checkpoint 或新的字段，以仓库实际能力为准，另立小任务实施。
单靠文本要求“禁止进入下一阶段”不是代码层强制，运行器必须真实检查阶段结果才有硬约束。
不新增“根因引擎”、多 Agent 调度系统、知识图谱或向量数据库。

## 保存位置与隐私

沿用仓库既有缺陷编号和记录目录。没有既定目录时可用 docs/bugs/<id>/，这只是默认建议。
优先提交脱敏输入、可重复脚本与断言；生产敏感证据留在受控系统，本地只存最小脱敏副本。
多名 Agent 共享同一证据版本，避免不同副本得出互相矛盾的“最终结论”。
